# PoC-рация (учебный проект) — код

Здесь находится C++-код приложения «рация» поверх интернета (PoC, Push-to-Talk).
Полный план разработки — в `/workspace/ROADMAP.md`.

## Что уже сделано (Этап 2: каркас + сеть)

```
poc-radio/
├── poc-radio.pro            # "рецепт" сборки для qmake (так собирает Aurora SDK)
├── src/
│   ├── main.cpp             # точка входа; пока консольная тестовая версия
│   ├── radiostate.h/.cpp    # «мозг» рации: режимы Offline / Listening / Talking
│   └── signalingclient.h/.cpp # «почтальон»: TCP-соединение с сервером
├── tests/
│   └── mock_server.py       # учебный сервер на Python для проверки без настоящего сервера
└── rpm/
    ├── poc-radio.spec       # ГЛАВНЫЙ «рецепт» пакета: %build через qmake+make
    └── poc-radio.yaml       # резерв/документация (spec приоритетнее)
```

## Правила для файлов в rpm/ (чтобы сборка в Aurora SDK не падала)

| Файл | Кодировка | Почему |
|------|-----------|--------|
| `poc-radio.spec` | **только ASCII** (комментарии и `%description` — по-английски) | rpmbuild читает spec в кодировке таргета; UTF-8 с кириллицей даёт `can't parse` и «Name/Version/Summary/License field must be present». Кроме того, директивы с `%` в строках комментариев вызывают `Macro expanded in comment` |
| `poc-radio.yaml` | UTF-8 допустим, но символов `%` быть не должно | это YAML: `%` ломает разбор (`found character '%' that cannot start any token`) |

Если в `rpm/` лежит `*.spec`, sfdk использует его как есть и **не** перегенерирует
spec из yaml — поэтому вся логика сборки (`qmake-qt5` + `make`, установка в `/usr/bin`)
живёт именно в spec. После любой правки этих файлов обязательно закрыть проект в
Qt Creator и удалить каталог `build/…/.sfdk` (там остаётся прошлый сгенерированный spec).

## Архитектура в двух словах

- **SignalingClient** только возит текстовые строки по сети. Не понимает, что они значат.
- **RadioState** принимает решения («можно ли говорить?», «кто спикер?») и шлёт команды.
- Так разделено специально: когда подключим аудио и интерфейс, «мозг» не придётся переписывать.

## Протокол обмена (одна строка = одно сообщение)

| Клиент → сервер     | Сервер → клиент              | Смысл                                  |
|---------------------|------------------------------|----------------------------------------|
| `JOIN <канал> <имя>`| `ACK JOINED`                 | вход в канал                           |
| `PTT_START`         | `ACK PTT_GRANTED` / `ERROR BUSY <кто>` | запрос эфира (кнопка нажата)    |
| `PTT_STOP`          | `ACK PTT_RELEASED`           | отпустили кнопку                       |
| —                   | `SPEAKER <имя>` / `SPEAKER`  | кто начал / закончил говорить          |
| —                   | `USERS <список>`             | кто в канале                           |
| `LEAVE`             | `ACK LEFT`                   | выход из канала                        |

## Как собрать и проверить (на обычном Linux с Qt5)

```bash
sudo apt install qtbase5-dev qt5-qmake python3
cd poc-radio
qmake && make -j4

# терминал 1 — учебный сервер:
python3 tests/mock_server.py 5000

# терминалы 2 и 3 — два «радиотелефона» (имена различаются таймерами запуска):
./poc-radio --server 127.0.0.1 --port 5000
```

Проверено: второй клиент получает `ERROR BUSY`, пока первый держит эфир —
«эфир действительно общий, говорит только один». ✅
